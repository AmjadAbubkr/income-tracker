# Requirements: IncomeTrack — Business Income & Sales Tracker

**Defined:** 2026-05-17
**Core Value:** A business can sign up, add their items with flexible categories, record sales and expenses, and instantly see their revenue dashboard — the complete end-to-end flow must work flawlessly.

## v1 Requirements

### Authentication

- [x] **AUTH-01**: User can create account with email and password
- [x] **AUTH-02**: User can log in with email and password
- [x] **AUTH-03**: User session persists across browser refresh
- [x] **AUTH-04**: User can log out from any page

### Dashboard

- [x] **DASH-01**: User sees revenue, expense, and net profit summary cards
- [x] **DASH-02**: User can toggle between daily, monthly, and all-time views
- [x] **DASH-03**: User sees revenue vs expenses chart
- [x] **DASH-04**: User sees top products/items ranked by revenue
- [x] **DASH-05**: User sees recent activity feed (latest sales and expenses)

### Product/Item Management

- [x] **PROD-01**: User can add a product/item with name, price, category, and optional description
- [x] **PROD-02**: User can edit an existing product/item
- [x] **PROD-03**: User can delete a product/item
- [x] **PROD-04**: User can create and assign custom categories to products
- [x] **PROD-05**: User can track optional inventory/stock quantity per product

### Sales Recording

- [x] **SALE-01**: User can record a sale with product, quantity, amount, and date
- [x] **SALE-02**: User can edit an existing sale record
- [x] **SALE-03**: User can delete a sale record
- [x] **SALE-04**: User can view sales history with date and product filtering
- [x] **SALE-05**: User can enter multiple sales in bulk (batch entry)

### Expense Tracking

- [x] **EXP-01**: User can record an expense with category, amount, date, and description
- [x] **EXP-02**: User can edit an existing expense
- [x] **EXP-03**: User can delete an expense
- [x] **EXP-04**: User can view expense history with date and category filtering

### Subscription Management

- [x] **SUB-01**: User can track business subscriptions (recurring costs) with name, amount, billing cycle, and next billing date
- [x] **SUB-02**: User can track customer subscriptions (recurring revenue) with customer name, service, amount, billing cycle, and next billing date
- [x] **SUB-03**: System auto-generates expense entries when business subscription billing date arrives
- [x] **SUB-04**: System auto-generates income entries when customer subscription billing date arrives

### Reporting & Export

- [x] **RPT-01**: User can export daily sales to Excel
- [x] **RPT-02**: User can export monthly sales to Excel
- [x] **RPT-03**: User can download a full JSON backup of their data
- [x] **RPT-04**: User can restore data from a JSON backup file
- [x] **RPT-05**: User can view a period summary report (revenue, expenses, net profit)
- [x] **RPT-06**: User can export a PDF report of their financial summary

### Notifications

- [x] **NOTF-01**: User receives an alert when a product's stock is low (≤5 items)
- [x] **NOTF-02**: User receives a reminder when a subscription billing date is within 3 days

### Settings

- [x] **SET-01**: User can select their default currency
- [x] **SET-02**: User can toggle between dark and light theme
- [x] **SET-03**: User can switch between English, French, and Arabic languages
- [x] **SET-04**: User can view and edit their profile (name, email)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Full double-entry accounting | Scope explosion — this is an income tracker, not an accounting system |
| Payroll processing | Different product domain, high regulatory complexity |
| CRM / pipeline management | Not core to income tracking |
| Warehouse inventory management | Overkill for target audience |
| Bank feed integration (Plaid/Tiller) | High complexity, defer to validate product-market fit first |
| OAuth / social login | Email/password sufficient for v1, adds dependency complexity |
| Team collaboration / multi-user per business | Single-owner model for v1, adds RBAC complexity |
| Invoice generation | Sales recording is the focus, not billing clients |
| Mobile native app | Responsive web covers mobile use cases for v1 |
